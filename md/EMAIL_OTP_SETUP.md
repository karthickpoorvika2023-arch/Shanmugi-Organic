# Supabase email OTP signup setup

The signup page now uses Supabase email/password signup. Supabase sends the **Confirm sign up** email; the shopper enters its OTP on `verify-otp.html`, then signs in with the password. The mobile field is contact information only; **it is not verified**.

For project `ufhlmdqkqdkcohpbzdux`:

1. In **Authentication → Providers → Email**, enable Email and **Confirm email**. In **Authentication → Settings**, enable **Allow new users to sign up**. Without both switches, the signup form deliberately refuses to create an account. Existing accounts are not recreated; use sign-in or password recovery for them.
2. In **Authentication → Emails → Confirm sign up** (not **Reset password**), replace the **Body** with the contents of [`CONFIRM_SIGNUP_OTP_TEMPLATE.html`](CONFIRM_SIGNUP_OTP_TEMPLATE.html), check **Preview**, and click **Save changes**. The card follows the reference screenshot's layout but says **Confirm Your Email** and has no reset button. The important placeholder is exactly `{{ .Token }}`: Supabase generates the code and sends it to the address used at signup; do not generate a code in browser JavaScript. The project's `mailer_otp_length` was changed from 8 to **6** and `mailer_otp_exp` remains 3600 (60 minutes), so `verify-otp.html` shows six boxes and verifies it using `verifyOtp({ email, token, type: 'email' })`. If these Supabase settings change, update the template's expiry copy and `OTP_LENGTH` on that page to match. This template is for *new-account confirmation*, not an OTP on every password sign-in.
3. Configure **Authentication → SMTP Settings** with your mail provider's SMTP credentials and sender address before sending to public shoppers. Supabase's default mail sender is for testing, has delivery restrictions and low quotas. Review the **Authentication → Rate Limits** for both signup emails and resends. Never add SMTP credentials or the service-role key to frontend files.
4. Test with a *new* email address using a deployed HTTPS site: sign up → receive an email (check Spam) → enter its six-digit code on `verify-otp.html` → sign in. Codes emailed before the switch may still have eight digits; use **Resend** to request a fresh six-digit code. The signup email template must actually display `{{ .Token }}` or there is no code to type. OTP expiry and resend restrictions are controlled by Supabase; email delivery requires working SMTP and may be rate-limited.

The Supabase project's email OTP length has been updated to six; deploying only these files to a different project does not change that project's dashboard settings. An authorized project owner must save the template in the dashboard if it is not already active. Do not send real OTPs, passwords, or SMTP credentials in screenshots or chat.
